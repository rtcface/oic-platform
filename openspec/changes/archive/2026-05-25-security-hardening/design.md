# Design: Security Hardening

## Technical Approach

This design implements the security hardening specified in `proposal.md` by migrating the package management from NPM to PNPM, disabling execution of arbitrary installation scripts, and whitelisting the critical `esbuild` dependency. This ensures defense-in-depth while maintaining Angular 13 compatibility.

## Architecture Decisions

| Decision | Option (Choice) | Tradeoff | Decision / Rationale |
|---|---|---|---|
| **Script Execution Policy** | Local `.npmrc` with `ignore-scripts=true` | Blocks all lifecycle scripts. Requires manual overrides for trusted binaries. | **Choice**. Enforces project-level Defense in Depth regardless of individual developer machine configuration. |
| **Dependency Resolution** | Local `.npmrc` with `shamefully-hoist=true` | Creates flat `node_modules` layout (similar to npm). Reduces pnpm strict encapsulation. | **Choice**. Required because the Angular 13 compiler and third-party modules fail to resolve nested dependencies under default pnpm non-hoisted nested layout. |
| **Build Tooling Execution** | Add `esbuild` to `pnpm.onlyBuiltDependencies` | Allows trusted binary lifecycle scripts to execute. Increases risk slightly for the whitelisted package. | **Choice** (vs manually rebuilding or permanent `--ignore-scripts`). `esbuild` is a trusted compiler dependency required for CSS/JS minification. Whitelisting it prevents build failures while keeping all other package scripts blocked. |

## Data Flow

```text
Developer/CI Running Installs:
[pnpm install]
     │
     ├──► Read .npmrc (ignore-scripts=true, shamefully-hoist=true)
     │         │
     │         ├─► Blocks all dependency scripts except whitelisted ones
     │         └─► Flattens node_modules directory
     │
     └──► Read package.json (pnpm.onlyBuiltDependencies)
               │
               └─► Allows esbuild execution to link native binary
```

## File Changes

| File | Action | Description |
|------|--------|-------------|
| `.npmrc` | Create | Root-level pnpm/npm configuration: `ignore-scripts=true`, `shamefully-hoist=true`, and `audit=true`. |
| `package.json` | Modify | Add `pnpm` configuration block containing `onlyBuiltDependencies: ["esbuild"]`. |
| `package-lock.json` | Delete | Replaced by `pnpm-lock.yaml`. |
| `pnpm-lock.yaml` | Create | Main lockfile for dependencies, auto-generated by running `pnpm import` / `pnpm install`. |

## Interfaces / Contracts

### `package.json` modification
```json
{
  "pnpm": {
    "onlyBuiltDependencies": [
      "esbuild"
    ]
  }
}
```

### `.npmrc` configuration
```ini
ignore-scripts=true
shamefully-hoist=true
audit=true
```

## Testing Strategy

| Layer | What to Test | Approach |
|-------|-------------|----------|
| Integration | Lockfile Creation | Run `pnpm import` to convert `package-lock.json` to `pnpm-lock.yaml`, followed by `pnpm install`, and verify `pnpm-lock.yaml` is correctly generated. |
| Integration | Dev Server Compilation | Run `ng serve` locally to verify development compilation and check if the `esbuild` binary resolves correctly. |
| Integration | Production Bundling & Minification | Run `ng build --configuration production` to verify production minification and verify the final assets output. |
| Unit | Testing suite | Run `ng test --watch=false --browsers=ChromeHeadless` to verify all Jasmine unit tests pass successfully. |

## Migration / Rollout

1. Generate `pnpm-lock.yaml` using `pnpm import`.
2. Write `.npmrc` with secure defaults.
3. Update `package.json` with the `pnpm.onlyBuiltDependencies` block.
4. Delete `package-lock.json` and the old `node_modules` folder.
5. Run `pnpm install` and verify the lockfile matches.
6. Verify local dev and production builds.
